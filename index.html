Enterprise data platform on Microsoft Fabric, built from zero

Problem
A fire-protection company with data spread across an Odoo ERP, Salesforce, Procore, InspectPoint, ADP and SharePoint, an IT team new to Fabric, and reporting that lived in one-off dataflows nobody could maintain.
Built
Sole data engineer embedded with IT leadership. Config-driven, metadata-driven ingestion into a medallion lakehouse (six source systems; PostgreSQL read replicas, the Salesforce connector, Delta Sharing, REST APIs and file drops), incremental loads with watermarks and MERGE patterns, a gold-layer star schema in a Fabric Warehouse refreshed by stored procedures, DirectQuery and Direct Lake semantic models, and an operational layer of config tables, run logging and a threshold-based data-quality framework. Then retired the legacy reports into governed gold models: unified time entries across ERP and field-ops systems with timecard-lateness analytics, and sales commissions.
Solved
PostgreSQL WAL conflicts on the read replica (retries, chunked loads), unscaled numerics breaking Spark casts (dynamic precision), and Fabric's own constraints: no nested procs, no ALTER TABLE, DirectQuery and Direct Lake limits.
Outcome
Production platform in a few months, plus a multi-session Fabric and Power BI training program delivered to the 8-to-10-person IT team.
